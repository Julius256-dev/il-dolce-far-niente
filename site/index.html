Get started

Install it after you have an app, in any stack, in a Git repository. Node.js 22 or newer.

New project

  1. Scaffold your app, for example with create-next-app.
  2. Run npx il-dolce-far-niente@latest in its root.
  3. Restart your agent and run /onboard.
  4. Write your plans, then run /overview.

Existing app

  1. Run npx il-dolce-far-niente@latest in its root.
  2. Restart your agent and run /adopt.
  3. It surveys what's shipped and drafts the plans from the code.
  4. Review the plans, then run /overview.

Then run /ci once, so every change has to pass one Verify command (typecheck, tests, build).

One loop for every feature

Each feature goes through the same steps, whether you build one at a time or several at once.

  1. /featureSpecA written plan you approve before any code.
  2. /implementBuildSmall steps, each tested before the next.
  3. /checkProveChecked against the running app.
  4. /auditReviewA fresh agent that never saw the build.
  5. /completeLandArchived, then merged with your approval.

Several at once with /avengers

Mark what each build-plan item waits for with /plan-graph. Then /avengers builds every unblocked item in its own worktree, with its own planner, builder and reviewers. You approve all the specs in one go. Finished items land one at a time on wave/1, and the whole wave gets a final review before it waits for your merge.

  • Items that touch the same files, or both handle payments or SMS, go in separate waves.
  • Serious review findings block landing until a re-review closes them.
  • Agents never push, publish or deploy.

Fast, without losing control

Built on AI Blueprint's feature loop and Matt Pocock's engineering skills.

Plans live in files

Plans, specs, review findings and history are plain Markdown in your repo. Any teammate or agent can pick up where the last one stopped.

Reviews you can trust

Reviewers start fresh and check standards, the spec, and security and quality when the work is sensitive. Payments and SMS always count as sensitive.

The right model per job

By default Opus 5.5 plans and reviews, and Sonnet 5.5 builds. Change any role for the team, or just for yourself, with /models.

Install for your tool

Every route installs the same version. The plugins add an install skill: ask your agent to install Il Dolce Far Niente and approve the command it shows.

npx il-dolce-far-niente@latest

Update later with npx il-dolce-far-niente@latest update. Files you changed are never overwritten without asking.

claude plugin marketplace add Julius256-dev/il-dolce-far-niente
claude plugin install il-dolce-far-niente@julius256-dev

Questions

Will it push code or change my main branch on its own?

No. Agents never push, publish or deploy, and a hook blocks them from touching your main branch. A finished wave waits on its own branch until you merge it.

Do I need Claude Code?

No. The single-feature loop works in Claude Code, Codex, GitHub Copilot, OpenCode and Antigravity. Parallel waves need a tool that runs background helper agents with their own model, such as Claude Code. Elsewhere, /continuous builds your plan one feature at a time with the same checks.

Isn't running many agents expensive?

Scripts handle the bookkeeping and each agent reads only what its job needs. On a measured four-feature wave this cut the cost by 28% compared with the first version. You can cap how many features run at once.

Can I use it on classified or client-restricted code?

Only after the client confirms in writing whether the code may leave their premises. The restricted profile keeps every review on, turns web research off and works with a locally hosted model. See the restricted repositories guide.

Is it free?

Yes. It's open source under the MIT licence. You pay only for the AI tool and models you already use.
