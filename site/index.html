The agents build. You approve.

Il Dolce Far Niente builds several features of your app at the same time. Each one gets its own Git worktree, a planner, a builder, and reviewers who never saw the build. Nothing reaches your main branch until you say yes.

npx il-dolce-far-niente@latest

Free and open source. Works with Claude Code, Codex, GitHub Copilot, OpenCode and Antigravity, on any stack.

What the name means

Italian, pronounced eel DOHL-chay far NYEN-tay

ilthe dolcesweet fardoing nientenothing

“The sweetness of doing nothing”: the Italian art of unhurried, guilt-free idleness, enjoyed because the work is in good hands.

That's the idea here. The agents plan, build and review; you keep every decision, from approving the specs to merging the wave.

Five steps to your first feature

You need an app in a Git repository, in any stack, and Node.js 22 or newer.

  1. Install

    From the root of your app run npx il-dolce-far-niente@latest. It adds the skills and a blueprint/ folder for plans and history.

  2. Onboard

    Restart your agent and run /onboard. On an app that already has features, run /adopt.

  3. Plan

    Write blueprint/project-plan.md and blueprint/build-plan.md, or let /discovery interview you. Then /overview.

  4. Add checks

    Run /ci once for a single Verify command that every change has to pass.

  5. Build

    One feature with /feature, /implement, /check, /complete. Several with /plan-graph then /avengers.

What happens in a wave

Every feature still goes through the full single-feature loop. Only the scheduling changes.

  1. Pick what can start

    Build-plan items say what they wait for, like _(after: 2, 3)_. Items that touch the same files, or both handle payments or SMS, wait for a later wave.

  2. Plan every feature

    A planner writes each spec in its own worktree, and you approve them together in one packet.

  3. Build side by side

    Builders work test-first, one small verified step at a time, each on its own port.

  4. Review with fresh eyes

    Reviewers who never saw the build check the coding standards and the spec, plus security and quality when the work is sensitive. A serious finding blocks landing until a re-review closes it.

  5. Land one at a time

    Each feature is archived and squashed onto wave/<n>, and Verify runs again after every landing.

  6. You merge

    A last review covers the whole wave, then it waits for you. Nothing is ever pushed for you.

Built from two proven toolkits

AI Blueprint's feature loop

A spec you approve, small verified steps, proof against the running app, a fresh review, and an archive. Plans, findings and history are plain files in your repo, so nothing important lives only in a chat.

Matt Pocock's engineering skills

Two-axis code review, test-driven development, issue triage, wayfinding through foggy projects, architecture surveys and retros, wired into the same files.

Models per role
Opus 5.5 plans and reviews, Sonnet 5.5 builds, by default. Change any role for the team or only for yourself with /models.
Payments and SMS
PesaPal, Flutterwave, escrow, payouts and Africa's Talking, webhooks included, always get an audit and an independent review.
Restricted code
For classified or regulated work, the client's written answer on whether code may leave the premises comes first. A hook enforces it, and a locally hosted model works when the answer is no.
Web and mobile
Verify recipes for Next.js with pnpm, Expo and Flutter, and a mobile check that proves features with widget tests and a simulator screenshot.
Guardrails
Every helper agent runs behind a hook that blocks pushes, publishing, deploys and any change to your main branch.

Install for your tool

Every route installs the same version into your repo. The plugins add one install skill: ask your agent to install Il Dolce Far Niente and approve the command it shows.

npx il-dolce-far-niente@latest

Run it in the root of your app. Update later with npx il-dolce-far-niente@latest update; files you changed are never overwritten without asking.

claude plugin marketplace add Julius256-dev/il-dolce-far-niente
claude plugin install il-dolce-far-niente@julius256-dev

The plugin updates itself.

codex plugin marketplace add Julius256-dev/il-dolce-far-niente
codex plugin add il-dolce-far-niente@julius256-dev

In Codex, type $feature where this page says /feature.

copilot plugin marketplace add Julius256-dev/il-dolce-far-niente
copilot plugin install il-dolce-far-niente@julius256-dev

Update with copilot plugin update il-dolce-far-niente.

npx skills@latest add Julius256-dev/il-dolce-far-niente

Works for Cursor, OpenCode, Windsurf and other agents that read skills.

Questions

Will it push code or change my main branch on its own?

No. Agents never push, publish or deploy, and a hook blocks them from touching your main branch. A finished wave waits on its own branch until you merge it.

Does it work on an app I've already built?

Yes. Install it, then run /adopt instead of /onboard. It surveys what's already shipped and writes the plans from the code.

Do I need Claude Code?

No. The single-feature loop works in Claude Code, Codex, GitHub Copilot, OpenCode and Antigravity. Parallel waves with /avengers need a tool that runs background helper agents with their own model, such as Claude Code. Elsewhere, /continuous builds the plan one feature at a time with the same checks.

Isn't running many agents expensive?

Scripts do the bookkeeping, each agent reads only the files its job needs, and the merger only runs when a landing conflicts. On a measured four-feature wave that cut the cost by 28% against the first version. You can also cap how many features run at once.

Can I use it on classified or client-restricted code?

Only after the client says in writing whether the code may leave their premises. The restricted profile keeps every review on, turns web research off and works with a locally hosted model. Read the restricted repositories guide first.
