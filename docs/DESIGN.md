# Il Dolce Far Niente — design contract

This file is the contract every skill, script and test in this repo follows.
Change it first when the design changes.

## What this project is

AI Blueprint's file-backed, gated feature loop, extended with:

- `/avengers`: build several build-plan features at once, each in its own Git
  worktree, then land them one at a time onto an integration branch;
- a curated set of Matt Pocock's skills (`mp-*`) wired into Blueprint's files;
- per-role model selection (`/models`).

The repository root is the install template, as in AI Blueprint: the installer
copies `AGENTS.md`, `CLAUDE.md`, `.agents/`, `.claude/` and `blueprint/` into a
user's project.

## Repository layout

| Path | Role |
| --- | --- |
| `skills/<name>/` | Single source of every skill (Claude form) |
| `.claude/skills/`, `.agents/skills/` | Generated by `npm run build:adapters`; never edit by hand |
| `.claude/agents/` | Subagent definitions installed into projects |
| `.claude/hooks/` | Hook scripts referenced by subagent definitions |
| `blueprint/` | Project template: config, plans, context, history |
| `evals/routing/` | One routing eval per skill |
| `packages/il-dolce-far-niente/` | Installer and `blueprint` CLI (fork of `create-ai-blueprint`) |
| `plugin/` | Thin Claude Code plugin that installs and updates a project |
| `upstream/` | Pristine `git subtree` copies of AI Blueprint and Matt Pocock's skills |
| `.upstream-base/` | Transformed upstream files at the last sync (merge base) |
| `upstream.lock.json` | Upstream sources, pinned commits, path mappings, skill renames |
| `scripts/` | `sync-upstream.ts`, `build-adapters.ts`, `validate.ts`; `scripts/blueprint/` holds Blueprint's own dev scripts |

## Skill rules

- `name` matches the folder, kebab-case, at most 64 characters.
- `description` at most 400 characters; all descriptions together at most 10,000.
- Every `SKILL.md` contains, right after its H1, the line:
  `**Context reuse:** Reuse any required file already loaded in project instructions or the current session. Read it again only if absent, changed, or exact current bytes or line references are needed.`
- **Orchestrators** (user-invoked, have `disable-model-invocation: true`): every
  Blueprint skill plus `avengers`, `models`, `plan-graph`, `mp-triage`,
  `mp-wayfinder`, `mp-architecture`, `mp-retro`, `mp-grill`.
- **Disciplines** (model-invoked, no flag): `mp-tdd`, `mp-grilling`,
  `mp-domain-modeling`, `mp-codebase-design`, `mp-code-review`,
  `mp-diagnosing-bugs`, `mp-research`, `mp-pr`, `mp-writing-for-agents`.
- An orchestrator may load disciplines. It never invokes another orchestrator,
  except `avengers`, which applies the documented behavior of `brief`, `feature`,
  `implement`, `check`, `audit` and `complete` inside each worktree (the same way
  Blueprint's `continuous` does).
- Every Matt Pocock folder carries `UPSTREAM.md` naming its source path and MIT
  licence.

All new keys are optional; a missing key means the default shown.

```json
  "tracker": {
    "kind": "local",
    "doc": "blueprint/context/tracker.md",
    "labels": {
      "bug": "bug",
      "enhancement": "enhancement",
      "needs-triage": "needs-triage",
      "needs-info": "needs-info",
      "ready-for-agent": "ready-for-agent",
      "ready-for-human": "ready-for-human",
      "wontfix": "wontfix"
    }
  },
  "domainDocs": { "glossary": "GLOSSARY.md", "adr": "docs/adr" },
  "avengers": {
    "maxConcurrent": 3,
    "specApproval": "batch",
    "integrationBranchPrefix": "wave/",
    "worktreeRoot": "../.worktrees",
    "serializeWhen": ["shared-files", "migration", "auth", "payments", "config"],
    "finalIntegrationAudit": true,
    "portBase": 4100
  },
  "models": {
    "main": "claude-opus-5-5",
    "subagentDefault": "claude-sonnet-5-5",
    "roles": {
      "planner": "claude-opus-5-5",
      "reviewer-lens": "claude-opus-5-5",
      "reviewer-standards": "claude-opus-5-5",
      "reviewer-spec": "claude-opus-5-5",
      "implementer": "claude-sonnet-5-5",
      "merger": "claude-sonnet-5-5",
      "explorer": "claude-sonnet-5-5"
    },
    "effort": {
      "planner": "medium",
      "reviewer-lens": "medium",
      "reviewer-standards": "medium",
      "reviewer-spec": "medium"
    },
    "reviewerMustDiffer": true
  }
}
```

Allowed values:

- `profile`: `client-delivery`, `product`, `restricted`, `custom`.
- `tracker.kind`: `local`, `github`, `gitlab`.
- `avengers.maxConcurrent`: integer 1–8; `1` disables parallel builds.
- `avengers.specApproval`: `batch` or `each`.
- `avengers.serializeWhen`: any of `shared-files`, `migration`, `auth`,
  `payments`, `config`, `sensitive`.
- Model values: `inherit`, an alias (`fable`, `opus`, `sonnet`, `haiku`, `best`,
  `opusplan`, optionally with `[1m]`), or a full ID matching
  `^claude-[a-z0-9-]+$`.
- `models.roles` keys: `planner`, `implementer`, `merger`, `reviewer-lens`,
  `reviewer-standards`, `reviewer-spec`, `explorer`.
- `models.effort` values: `low`, `medium`, `high`, `xhigh`, `max`.

`blueprint/config.local.json` (Git-ignored) may override `models` and
`avengers.maxConcurrent` for one developer. It never overrides safety settings.

## Build-plan dependency edges

A build-plan leaf may end with an `after` suffix listing the item numbers that
must be checked first:

```markdown
- [ ] 4. **Export reports** - CSV and PDF downloads _(after: 2, 3)_
```

`_(after: none)_` means the item depends on nothing. No suffix means the item
depends on every earlier unchecked item (Blueprint's serial behavior), so old
plans keep working. `plan-graph` writes these
suffixes; `avengers` reads them. Cycles are invalid.

## Subagent roles

| Role | Agent file | Default model | Writes |
| --- | --- | --- | --- |
| planner | `.claude/agents/planner.md` | Opus 5.5, medium | specs in its worktree |
| implementer | `.claude/agents/implementer.md` | Sonnet 5.5 | code, tests, spec checkboxes in its worktree |
| merger | `.claude/agents/merger.md` | Sonnet 5.5 | the feature's `/complete` work commit, then the integration branch |
| reviewer-lens | `.claude/agents/reviewer-lens.md` | Opus 5.5, medium | `findings.md`, `review.md` |
| reviewer-standards | `.claude/agents/reviewer-standards.md` | Opus 5.5, medium | nothing; returns new findings and verdicts on `fixed` ones |
| reviewer-spec | `.claude/agents/reviewer-spec.md` | Opus 5.5, medium | nothing; returns new findings and verdicts on `fixed` ones |
| explorer | `.claude/agents/explorer.md` | Sonnet 5.5 | `blueprint/research/` only |

Orchestrators resolve each role with `skills/models/scripts/resolve.mjs` and pass
the result as the per-call `model` parameter (the family name when the runtime
only accepts families); the agent file's `model` is a lower-precedence fallback.

## Landing a wave item

1. The item is reviewed against its own diff: base = its fork point on the
   integration branch, target = its review checkpoint.
2. The merger applies `/complete` Steps 0–2 on the feature branch while the
   review is current, recording `landing: wave-merge`, `baseRef` = the
   integration branch and `baseCommit` = the fork point. Live evidence is
   archived and reset, so no ledger travels between items.
3. The merger squash-merges the work commit onto the integration branch (one
   parent), resolving only build-plan ticks and additive conflicts, and reruns
   Verify. Any other conflict sends the item back for rework and full re-review.
4. A `wave-merge` archive is proven like a schema 2 pull-request archive. The
   wave reaches the default branch by fast-forward or a non-squash merge, so the
   proof survives.
5. Cross-item effects are covered by Verify after every landing and the
   wave-wide integration audit. No subagent may push, merge to the
default branch, publish or deploy; `.claude/hooks/block-remote-git.mjs` enforces
this for every role.

## Upstream sync

`npm run sync:upstream` three-way merges each mapped upstream file
(`git merge-file`, base from `.upstream-base/`). Our edits survive as long as
they don't touch the same lines as an upstream change; conflicts are left with
markers and reported. `.github/workflows/upstream-sync.yml` runs this weekly
after `git subtree pull` and opens a pull request.
