# Il Dolce Far Niente — design contract

This file is the contract every skill, script and test in this repo follows.
Change it first when the design changes.

## What this project is

AI Blueprint's file-backed, gated feature loop, extended with:

- `/avengers`: build several build-plan features at once, each in its own Git
  worktree, then land them one at a time onto an integration branch;
- a curated set of Matt Pocock's skills (`mp-*`) wired into Blueprint's files;
- per-role model selection (`/models`).

The repository root is the install template, as in AI Blueprint: the installer
copies `AGENTS.md`, `CLAUDE.md`, `.agents/`, `.claude/` and `blueprint/` into a
user's project.

## Repository layout

| Path | Role |
| --- | --- |
| `skills/<name>/` | Single source of every skill (Claude form) |
| `.claude/skills/`, `.agents/skills/` | Generated by `npm run build:adapters`; never edit by hand |
| `.claude/agents/` | Subagent definitions installed into projects |
| `.claude/hooks/` | Hook scripts referenced by subagent definitions |
| `blueprint/` | Project template: config, plans, context, history |
| `evals/routing/` | One routing eval per skill |
| `packages/il-dolce-far-niente/` | Installer and `blueprint` CLI (fork of `create-ai-blueprint`) |
| `plugin/` | Thin Claude Code plugin that installs and updates a project |
| `upstream/` | Pristine `git subtree` copies of AI Blueprint and Matt Pocock's skills |
| `.upstream-base/` | Transformed upstream files at the last sync (merge base) |
| `upstream.lock.json` | Upstream sources, pinned commits, path mappings, skill renames |
| `scripts/` | `sync-upstream.ts`, `build-adapters.ts`, `validate.ts`; `scripts/blueprint/` holds Blueprint's own dev scripts |

## Skill rules

- `name` matches the folder, kebab-case, at most 64 characters.
- `description` at most 400 characters; all descriptions together at most 10,000.
- Every `SKILL.md` contains, right after its H1, the line:
  `**Context reuse:** Reuse any required file already loaded in project instructions or the current session. Read it again only if absent, changed, or exact current bytes or line references are needed.`
- **Orchestrators** (user-invoked, have `disable-model-invocation: true`): every
  Blueprint skill plus `avengers`, `models`, `plan-graph`, `mp-triage`,
  `mp-wayfinder`, `mp-architecture`, `mp-retro`, `mp-grill`.
- **Disciplines** (model-invoked, no flag): `mp-tdd`, `mp-grilling`,
  `mp-domain-modeling`, `mp-codebase-design`, `mp-code-review`,
  `mp-diagnosing-bugs`, `mp-research`, `mp-pr`, `mp-writing-for-agents`.
- An orchestrator may load disciplines. It never invokes another orchestrator,
  except `avengers`, which applies the documented behavior of `brief`, `feature`,
  `implement`, `check`, `audit` and `complete` inside each worktree (the same way
  Blueprint's `continuous` does).
- Every Matt Pocock folder carries `UPSTREAM.md` naming its source path and MIT
  licence.

## Config additions (`blueprint/config.json`)

All new keys are optional; a missing key means the default shown, except
`models.roles` and `models.effort`: a role missing there falls through to
`subagentDefault`, then the agent file's `model`, then `inherit` (see
`skills/models/reference/resolution.md`). The template config lists every role
explicitly, so new projects get the team defaults below.

```json
{

  "tracker": {

      "enhancement": "enhancement",

      "needs-info": "needs-info",
      "ready-for-agent": "ready-for-agent",

  "domainDocs": { "glossary": "GLOSSARY.md", "adr": "docs/adr" },
  "avengers": {
    "maxConcurrent": 3,
    "specApproval": "batch",
    "integrationBranchPrefix": "wave/",
    "worktreeRoot": "../.worktrees",
    "serializeWhen": ["shared-files", "migration", "auth", "payments", "sms", "config"],
    "finalIntegrationAudit": true,
    "portBase": 4100

  "sensitive": {

      "implementer": "claude-sonnet-5-5",
      "merger": "claude-sonnet-5-5",
      "explorer": "claude-sonnet-5-5"
    },
    "effort": {
      "planner": "medium",

```

Allowed values:

- `profile`: `client-delivery`, `product`, `restricted`, `custom`.
- `tracker.kind`: `local`, `github`, `gitlab`.
- `avengers.maxConcurrent`: integer 1–8; `1` disables parallel builds.
- `avengers.specApproval`: `batch` or `each`.
- `avengers.serializeWhen`: any of `shared-files`, `migration`, `auth`,
  `payments`, `sms`, `config`, `sensitive` (`sensitive` serializes on every
  pattern category).
- `sensitive.patterns`: lowercase category names, each a non-empty list of
  case-insensitive regular expressions. Listed categories extend the built-in
  ones; payments and SMS can be extended but never removed. They are matched
  against build-plan lines, specs, changed paths and diffs.
- `research.web`: `false` blocks web tools through
  `.claude/hooks/data-handling.mjs`.
- `dataHandling.sourceMayLeavePremises`: `null`, `"yes"` or `"no"`; with
  `profile: "restricted"` the prompt hook refuses every prompt while it is
  `null`, and refuses cloud endpoints while it is `"no"`.
- Model values: `inherit`, an alias (`fable`, `opus`, `sonnet`, `haiku`, `best`,
  `opusplan`, optionally with `[1m]`), or a full ID matching
  `^claude-[a-z0-9-]+$`.
- `models.roles` keys: `planner`, `implementer`, `merger`, `reviewer-lens`,
  `reviewer-standards`, `reviewer-spec`, `explorer`.
- `models.effort` values: `low`, `medium`, `high`, `xhigh`, `max`.

`blueprint/config.local.json` (Git-ignored) may override `models` and
`avengers.maxConcurrent` for one developer. It never overrides safety settings.

## Build-plan dependency edges

A build-plan leaf may end with an `after` suffix listing the item numbers that
must be checked first:

```markdown
- [ ] 4. **Export reports** - CSV and PDF downloads _(after: 2, 3)_
```

`_(after: none)_` means the item depends on nothing. No suffix means the item
depends on every earlier unchecked item (Blueprint's serial behavior), so old
plans keep working. `plan-graph` writes these
suffixes; `avengers` reads them. Cycles are invalid.

## Subagent roles

| Role | Agent file | Default model | Writes |
| --- | --- | --- | --- |
| planner | `.claude/agents/planner.md` | Opus 5.5, medium | specs in its worktree |
| implementer | `.claude/agents/implementer.md` | Sonnet 5.5 | code, tests, spec checkboxes in its worktree |
| merger | `.claude/agents/merger.md` | Sonnet 5.5 | a merge of the wave into a feature branch, only after a conflicted landing |
| reviewer-lens | `.claude/agents/reviewer-lens.md` | Opus 5.5, medium | `findings.md`, `review.md` |
| reviewer-standards | `.claude/agents/reviewer-standards.md` | Opus 5.5, medium | `blueprint/.state/avengers/review-standards.json` only |
| reviewer-spec | `.claude/agents/reviewer-spec.md` | Opus 5.5, medium | `blueprint/.state/avengers/review-spec.json` only |
| explorer | `.claude/agents/explorer.md` | Sonnet 5.5 | `blueprint/research/` only |

Orchestrators resolve each role with `skills/models/scripts/resolve.mjs` and pass
the result as the per-call `model` parameter (the family name when the runtime
only accepts families); the agent file's `model` is a lower-precedence fallback.

## Landing a wave item

1. The item is reviewed against its own diff: base = its fork point on the
   integration branch, target = its review checkpoint
   (`avengers.mjs checkpoint`).
2. `land.mjs` applies `/complete` Steps 0–2 on the feature branch while the
   review is current: the safety pass (spec, steps, findings, receipt freshness,
   Verify), the source-tree capture and annotation with `landing: wave-merge`,
   `baseRef` = the integration branch and `baseCommit` = the fork point, the
   archive with resolved findings, receipt and try guide, the plan tick and its
   parent, the overview fingerprint, and the canonical stubs. Open, fixed and
   unverified findings stay in the ledger, as `/complete` requires.
3. It squash-merges the work commit onto the integration branch (one parent),
   resolving the bookkeeping files deterministically: build-plan ticks are
   unioned, ledgers are unioned by finding ID (a new entry whose bare ID is
   taken gets the next free ID and a `landed from` note on its **Found** line),
   and the fingerprint is recomputed. It then reruns Verify and proves the tip
   carries the archive unchanged.
4. Any other conflict, or a failed Verify, restores both branches to their state
   before the run. The orchestrator hands a conflict to the merger agent, which
   merges the wave into the feature branch; the item is then reviewed again in
   full before it lands.
5. A `wave-merge` archive is proven like a schema 2 pull-request archive. The
   wave reaches the default branch by fast-forward or a non-squash merge, so the
   proof survives. Cross-item effects are covered by Verify after every landing
   and the wave-wide integration audit. No subagent may push, merge to the
   default branch, publish or deploy; `.claude/hooks/block-remote-git.mjs`
   enforces this for every role.

## Keeping usage low

Cost is dominated by how many turns the orchestrator takes and how much context
each turn re-reads. So:

- **Scripts do the bookkeeping.** `avengers.mjs` (preflight, setup, state,
  verify, checkpoint, findings, record, gate, status) and `land.mjs` turn each
  multi-step job into one call with a compact JSON answer.
- **The orchestrator loads no other workflow skill.** Agents read the skill
  they apply; the orchestrator passes paths, IDs and SHAs.
- **Agents start without `AGENTS.md`.** Every subagent sets `omitClaudeMd: true`
  and its page lists the files its role reads; reviewers and the implementer
  preload only the discipline they use (`mp-code-review`, `mp-tdd`).
- **No agent for the happy path of landing.** The merger runs only on conflict.

## Team defaults

- **Sensitive work.** Payments and SMS are built-in sensitive categories. The
  `when-sensitive` lists in `/complete`, `/continuous` and `/autopilot` name
  them; `/avengers` also finds them deterministically (`avengers.mjs` matches
  `sensitive.patterns` against plan lines, specs and diffs), turns on the lens
  review and serializes items that share a category.
- **Stacks.** `/ci` carries Verify recipes for Next.js/TypeScript (pnpm),
  Expo/React Native, Flutter and mixed repositories; `/check` carries a mobile
  recipe (component or widget tests, then a simulator screenshot, a Flutter
  golden or an Expo web screenshot) so the check gate finishes on mobile work.
- **Restricted work.** `skills/onboard/reference/restricted.md` is the process;
  `.claude/hooks/data-handling.mjs` enforces the recorded answer and
  `research.web`.
- **Cadence.** `/mp-retro` after every wave and `/mp-architecture` weekly; both
  write `blueprint/research/` notes and route accepted items to the findings
  ledger or the build plan.
- **Conventions.** The coding-standards template opens with Team conventions
  (Conventional Commits, no AI attribution, branch prefixes, pnpm over Bun);
  `skills/onboard/reference/standards/` holds Expo and Flutter starting points.

## Upstream sync

`npm run sync:upstream` three-way merges each mapped upstream file
(`git merge-file`, base from `.upstream-base/`). Our edits survive as long as
they don't touch the same lines as an upstream change; conflicts are left with
markers and reported. `.github/workflows/upstream-sync.yml` runs this weekly
after `git subtree pull` and opens a pull request.
